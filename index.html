Duality: สลับ · ↔ + และ 0 ↔ 1 โดยไม่เปลี่ยนตัวแปร — theorem ที่จริง dual ก็จริง (เป็น meta-theorem ไม่ใช่วิธีแปลงนิพจน์) ส่วน generalized de Morgan สลับ · ↔ +, 0 ↔ 1 และ complement ตัวแปร ได้ f'

ตัวอย่าง: ลดรูป carry-out ของ full adder Cout = A'BCin + AB'Cin + ABCin' + ABCin
  1. เพิ่ม ABCin อีก 2 ชุด (idempotency: X = X + X) แล้วจับคู่กับแต่ละพจน์
  2. (A'BCin + ABCin) = BCin (uniting), (AB'Cin + ABCin) = ACin, (ABCin' + ABCin) = AB
  3. ได้ Cout = BCin + ACin + AB
จุดที่มักพลาด
  • (A·B)' ≠ A'·B' — ที่ถูกคือ A' + B'

  • คิดว่า XOR ถูกเพราะวาดง่าย — จริงๆ แพงที่สุด (16 switches)

  • จำนวนฟังก์ชัน = 2^(2^n)
  • Consensus: XY + YZ + X'Z = XY + X'Z
  • NAND หรือ NOR ตัวเดียวเป็น minimal set

นิยาม

  • Implicant: 1 ช่อง หรือกลุ่มของ ON/DC ที่รวมเป็น subcube ได้
  • Prime implicant: implicant ที่ขยายรวมกับตัวอื่นให้ใหญ่ขึ้นไม่ได้แล้ว
  • Essential prime implicant: prime implicant ที่เป็นตัวเดียวที่คลุม 1 บางช่อง → ต้องอยู่ในทุก cover; DC ใช้ขยาย prime ได้แต่ไม่ทำให้เป็น essential

Two-level ด้วย NAND / NOR

  • NAND-NAND = SOP: แทน AND ด้วย NAND, OR ที่ input กลับขั้ว = NAND (A' + B' = (AB)')
  • NOR-NOR = POS: แทน OR ด้วย NOR, AND ที่ input กลับขั้ว = NOR (A'·B' = (A + B)')
  • แปลงวงจร: ใส่ “bubble” เป็นคู่ (conservation of inversions) — Z = [(AB)'·(CD)']' = AB + CD
  • AOI (AND-OR-Invert): หา F' แบบ SOP โดยจับกลุ่ม 0 แล้ว invert, เช่น A xor B = (A'B' + AB)'

Multi-level logic: เช่น x = ADF + AEF + BDF + BEF + CDF + CEF + G = (A + B + C)(D + E)F + G — วงจรเล็กลง fan-in น้อยลง อาจเร็วขึ้น แต่ออกแบบ/วิเคราะห์ยากกว่า เครื่องมือ optimize ยังไม่ดีเท่า two-level

จุดที่มักพลาด
  • ลืมว่าขอบ K-map วนติดกัน (รวมมุมทั้งสี่)
  • จับกลุ่มขนาด 3 หรือ 6 (ต้องเป็น 1, 2, 4, 8)
  • นับ prime ที่คลุมแต่ DC ว่าเป็น essential
ต้องจำ
  • NAND-NAND ↔ SOP, NOR-NOR ↔ POS
  • Essential = คลุม 1 บางช่องได้ตัวเดียว

เกตใช้เวลาในการเปลี่ยน output (propagation delay) ถ้าเส้นทางสัญญาณมี delay ไม่เท่ากัน output อาจกระพริบชั่วคราว (glitch/hazard) — อันตรายถ้า logic “ตัดสินใจ” ขณะ output ยังไม่นิ่ง (เช่นใช้เป็น asynchronous control)

ชนิดพฤติกรรม
Static 1-hazardควรเป็น 1 ตลอด แต่ได้ 1 → 0 → 1
Static 0-hazardควรเป็น 0 ตลอด แต่ได้ 0 → 1 → 0
Dynamic hazardควรเปลี่ยนครั้งเดียว แต่เปลี่ยนหลายครั้ง เช่น 0 → 1 → 0 → 1

การแก้ static hazard

  • 1-hazard: เพิ่มพจน์ redundant ให้ทุกคู่ของ 1 ที่อยู่ติดกันใน K-map ถูกคลุมโดยพจน์เดียวกัน
  • 0-hazard: ทำกับ complement / รูป POS ให้ทุกคู่ของ 0 ที่ติดกันถูกคลุม
  • วงจร multi-level: คำนวณ transient output function โดยถือว่า X กับ X' เป็นตัวแปรอิสระ (ห้ามใช้ X + X' = 1 หรือ X·X' = 0)
ตัวอย่าง: F = A'D + AC'
  1. ที่ C = 0, D = 1: F = A' + A ควรเป็น 1 เสมอ แต่ตอน A เปลี่ยน พจน์หนึ่งดับก่อนอีกพจน์ติด → static 1-hazard
  2. เพิ่ม consensus term: F = A'D + AC' + C'D
  3. รูป POS: F = (A' + C')(A + D) มี 0-hazard → เพิ่ม (C' + D)

HDL (Verilog) เบื้องต้น

  • Structural: instantiate เกตและต่อสายเหมือน schematic; Behavioral: บอกพฤติกรรม input/output
  • Continuous assignment: assign #6 out = a ^ b; (#6 = delay)
  • always block: always @(a or b) out = a ^ b; ทำงานเมื่อสัญญาณใน sensitivity list เปลี่ยน; testbench ใช้ initial ซึ่งทำครั้งเดียว
จุดที่มักพลาด
  • ลดรูปจนพจน์ consensus หายไป แล้วไม่ได้ตรวจ hazard
  • ใช้ X + X' = 1 ตอนวิเคราะห์ transient output
ต้องจำ
  • Hazard เกิดจาก delay ต่างกัน แก้ด้วยพจน์ redundant
  • Static-1: 1→0→1, Static-0: 0→1→0, Dynamic: เปลี่ยนหลายครั้ง

Multiplexer (MUX / selector)

2n data input, n select, 1 output — select เป็น index ของ input ที่ต่อออก output

2:1 Z = A'I0 + AI1 4:1 Z = A'B'I0 + A'BI1 + AB'I2 + ABI3 2^n:1 Z = Σ (mk · Ik), k = 0 … 2^n − 1
  • MUX 2n:1 implement ฟังก์ชัน n ตัวแปรใดก็ได้ (data input = 0/1 → lookup table)
  • MUX 2n−1:1 ก็พอ: ใช้ n−1 ตัวแปรเป็น select ส่วน data = ตัวแปรสุดท้าย, complement, 0 หรือ 1

Adder

Half adder: S = A xor B Cout = AB Full adder: S = A xor B xor Cin Cout = Cin(A + B) + AB = BCin + ACin + AB Subtract: A − B = A + B' + 1 (Cin = 1, เลือก B' ด้วย MUX/XOR)
  • Full adder: แบบมาตรฐาน 6 gates (2 XOR, 2 AND, 2 OR) หรือ half adder 2 ตัว + OR = 5 gates
  • Ripple-carry: carry ไล่ทีละ stage ใช้ 2 gate delays/stage → 4 บิต: C1@2, C2@4, C3@6, Cout@8; worst case คือ 1111 + 0001

Configurations

  • ลด hit time → cache เล็ก
  • Block size ใหญ่: spatial มากขึ้น แต่ miss penalty สูงขึ้น (ถ้าไม่ขยาย bus) และ temporal ลดลง (block น้อยลง)
  • Associativity: n-way มี n entry ต่อ index, conflict miss ลดลง แต่ต้องใช้ n comparator + MUX ใหญ่ (hit time อาจสูงขึ้น); fully associative ไม่มี index, conflict miss = 0
  • Replacement: LRU, round robin, FIFO, random — direct mapped ไม่ต้องเลือก (มีที่เดียว); ในทางปฏิบัติแยก cache ของ code และ data

TLB (Translation Lookaside Buffer)

  • cache ของ page table entry ที่ใช้ล่าสุด เวลาเข้าถึงใกล้ cache

Overlapped cache & TLB access

  • ใช้ high-order bits ของ VA ค้น TLB พร้อมกับใช้ low-order bits index cache — ทำได้เมื่อ index ของ cache อยู่ใน page offset (ไม่เปลี่ยนจากการแปลง)
  • ถ้า cache hit และ cache tag = PA → ส่งข้อมูล; ถ้า miss หรือ tag ≠ PA แต่ TLB hit → เข้า memory ด้วย PA จาก TLB; ไม่งั้นแปลง VA แบบปกติ

  3. Cache 32KB กับ page 4KB → ต้องเป็นอย่างน้อย 32KB / 4KB = 8-way
  • Cache ที่ใช้ virtual address: มีปัญหากับ shared memory (VA ต่างกันจากหลาย process ชี้ PA เดียวกัน)
